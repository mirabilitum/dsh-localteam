# DSH 局域网团队协作补丁

简体中文 | [English](README.md)

> 本补丁基于 **DSH 0.1.6-alpha.1**，沿用上游默认外观。
>
> **对接源码版本：** `0d1f50007f9bca3f52b06e1c3074fa14d5fb0720`（[上游提交](https://github.com/deepseek-ai/deepseek-harness/commit/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720)）。应用补丁时必须使用这一份源码；当前上游最新提交和其他 DSH 版本不在本版本适配范围内。

让一台自己的电脑成为小团队的 AI 协作服务器。

下载当前补丁：[`dsh-team-0.1.6-alpha.1.patch`](patches/dsh-team-0.1.6-alpha.1.patch)。

基于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)，为小团队、课题组和项目组增加成员登录、共享会话、协作控制权、项目目录管理和产物下载。管理员在一台电脑上部署，其他成员通过局域网中的浏览器访问，共用服务器上的项目文件和模型服务。

适合希望把资料、对话过程和项目成果放在一起，减少来回传文件、重复说明背景的小团队。服务器可以是办公室的电脑或专门准备的主机；使用期间需要保持开机、服务运行，并让成员的设备能够访问。

## 能做什么

- **一起看进度**：成员可以打开共享会话，查看对话、执行过程和已有输出，不必等负责人整理完再同步。
- **接着做任务**：需要沿用原对话时直接移交控制权；需要拆分任务时，在同一个项目下新开对话，继续使用已有文件。
- **统一放项目材料**：原始材料、中间数据、交付成果和临时文件分别存放，减少成品与草稿混在一起。
- **把服务器上的成果带走**：在浏览器里下载单个文件，或勾选多个产物打包下载到自己的电脑。
- **共用一套服务**：管理员集中配置模型凭据和成员信息，成员不需要各自安装一套 DSH。

## 团队怎样协作

### 同一个项目，共享文件和过程

项目是共同的工作目录，会话是围绕具体任务开展的对话。同一项目可以建立多个会话，分别处理资料整理、数据分析、报告编写等工作。

例如，甲先整理资料，乙可以直接查看甲的会话和输出，了解目前做到哪里。甲完成后，告诉乙成果放在哪里、下一步要做什么，乙就可以接着推进，不必再把整个项目打包传一遍。

接续工作有两种方式：

| 场景 | 操作方式 |
|---|---|
| 需要沿用当前对话的上下文 | 当前控制人在会话头部将控制权移交给下一位成员，对方继续该对话 |
| 需要开展另一项任务或重新组织对话 | 在**同一个项目目录下新开对话**，说明任务，并让 Agent 读取已有材料和成果 |

新对话可以访问同一项目里的文件，但不会自动继承其他对话的全部上下文。把重要结论、操作步骤和待办写进项目文件，会更方便下一位成员接手。

### 共同查看，按控制权操作

成员查看会话不需要接管控制权。发送提示词等受控操作由当前控制人执行，避免多人同时向同一会话下指令。

- 正常交接时，在会话头部的控制权入口选择接收成员。
- 控制人暂时离开时，默认闲置 **15 分钟**后，其他成员可以显式接管；等待时长由管理员配置。
- 启用项目写入串行化后，同一项目已有会话在执行受控写入任务时，另一个会话会收到忙碌提示，需要稍后重试。新开对话不会绕过这个限制。
- 不同项目可以分别推进，实际并行能力取决于服务器资源和模型服务。

## 权限怎样管理

权限分为成员登录、会话控制和 Agent 文件操作三个方面。

| 层面 | 使用方式 |
|---|---|
| 成员登录 | 管理员维护成员名册，成员凭姓名和邀请码登录；同一账号再次登录会使旧登录失效 |
| 会话控制 | 成员共同查看，当前控制人负责受控操作；需要换人时移交或按闲置规则接管 |
| 工作目录 | 管理员设置团队工作区和项目容器，目录选择器限定在配置范围内 |
| Agent 操作 | 按权限预设执行；需要超出当前权限的操作时进入审批流程 |

团队部署可以只保留两种常用权限预设：

- **read-only**：用于查看和分析，当前预设不允许写入。
- **workspace-write**：允许在工作区内写入，适合生成报告、处理数据和修改项目文件。

需要更大权限的操作由审批流程处理，不等于成员默认获得全盘操作权限。网页终端也可以由管理员关闭。

这是供相互信任的团队共用的工作环境，当前采用共享可见的协作方式，没有按成员划分私有项目。出网和环境变量未隔离，部分写入口尚未纳入协作控制；文件操作也还不能逐次追溯到具体成员。

## 项目产物怎样归类

通过目录选择器在项目容器内新建项目时，自动创建统一目录和项目规则文件 `AGENTS.md`，让成员和 Agent 按相同方式组织材料。

| 目录 | 用途 | 例子 |
|---|---|---|
| `input/` | 外部提供的原始材料，按项目规则保留原件，加工时另存副本 | 原始表格、参考文档、收到的数据包 |
| `build/` | 有复用价值、重新生成有成本的中间产物 | 清洗后的数据、数据库、索引 |
| `work/` | 准备交付、给他人查看或使用的成果 | 报告、图表、最终脚本 |
| `logs/` | 过程记录 | 处理说明、运行记录 |
| `sessions/<会话>/temp/` | 各会话自己的临时文件 | 试算草稿、临时脚本、下载缓存 |

使用时可以直接告诉 Agent：**“读取 input 中的材料，中间数据放 build，最终成果放 work。”**

目录骨架和规则明确区分各类文件，下载入口只开放 `work/` 中的成果。文件应由成员和 Agent 按规则归类，目前不会自动识别并搬运所有文件；也不要把临时草稿放进 `work/`，其他成员会将它们视为可交付成果。

## 远端成果怎样下载

文件生成在服务器上，成员可以通过浏览器保存到自己的电脑，无需登录服务器桌面。

1. 打开对应项目的会话。
2. 点击会话标题旁的下载图标，查看 `work/` 中的产物清单。
3. 只要一个文件时，点击该文件的“单独下载”。
4. 需要多个文件时，勾选后点击“下载所选”，保存为 ZIP。

下载不需要接管会话控制权。列表为空时，先确认成果是否已经写入 `work/`；`input/`、`build/`、`logs/` 和临时目录不会一起打包。超过服务端下载限制的文件需要拆分处理。

## 开始使用

**管理员**：准备一台能够被团队设备访问的电脑，安装指定版本的 DSH 并应用补丁，配置团队工作区、成员、模型凭据和监听地址，启动服务后分发访问链接与成员邀请码。

本版本对应的源码是提交 [`0d1f50007f9bca3f52b06e1c3074fa14d5fb0720`](https://github.com/deepseek-ai/deepseek-harness/tree/0d1f50007f9bca3f52b06e1c3074fa14d5fb0720)，不是会持续变化的上游 `master` 分支。以后 DSH 发布新版本时，需要重新检查补丁，必要时发布新的补丁版本。

```powershell
git clone https://github.com/deepseek-ai/deepseek-harness.git source
Set-Location source
git checkout 0d1f50007f9bca3f52b06e1c3074fa14d5fb0720
```

**团队成员**：打开管理员提供的带令牌链接，使用自己的姓名和邀请码登录，选择或新建项目，再创建会话开展工作。成员使用现代浏览器即可，不需要下载源码。

安装需要使用指定的源码版本，不能仅按相同版本号任意覆盖；具体版本定位和安装命令放在安装说明中。

访问地址由管理员启动自己的实例后生成。服务启动时，管理员将本机局域网地址和 DSH 打印出的带令牌链接发给成员；每个部署都有自己的访问链接，不存在所有安装共用的固定公网地址。

### 管理员先准备哪些目录

部署目录由你自己选择，不依赖补丁作者的电脑路径。下面以 Windows 的 `C:\DSH-Team` 为例；你可以换到有足够空间的其他位置，并在配置中使用对应路径。

| 目录 | 用途 |
|---|---|
| `source/` | 指定版本的 DSH 源码、依赖与构建产物 |
| `home/` | 团队实例配置、凭据和会话数据，即 `DSH_HOME` |
| `workspace/` | 团队工作区，即 `workspaceRoot` |
| `workspace/projects/` | 存放各个项目的容器，即 `projectsRoot`，同时作为目录选择器的根 |

先在 PowerShell 中创建配置与工作目录：

```powershell
$teamRoot = 'C:\DSH-Team' # 示例位置，可以自行更换
$teamHome = Join-Path $teamRoot 'home'
$teamWorkspace = Join-Path $teamRoot 'workspace'
$teamProjects = Join-Path $teamWorkspace 'projects'
New-Item -ItemType Directory -Force -Path (Join-Path $teamHome 'profiles\web'), $teamProjects | Out-Null
$env:DSH_HOME = $teamHome
```

将源码放在 `source/`，团队配置放在 `home/profiles/web/cordis.patch.yml`。在团队插件配置中，将 `workspaceRoot` 设为工作区的实际绝对路径、`projectsRoot` 设为项目容器的实际绝对路径；目录选择器的 `root` 也指向项目容器。YAML 中的 Windows 路径可使用单引号。

`DSH_HOME` 必须在每次启动时设置，或写入本机的启动脚本。它与源码目录、成员工作区分开存放。监听地址使用服务器自己的局域网 IP；成员访问服务器地址，不是自己电脑的 `localhost`。

### 管理员怎样创建成员

当前通过配置维护成员，没有网页自助注册或成员管理后台。管理员编辑团队实例的 `home/profiles/web/cordis.patch.yml`，在已有 `team-identity` 插件的 `config.members` 列表中添加成员。

下面是该列表的示例，**不是完整部署配置**；保留插件中其他配置项，不要重复插入插件：

```yaml
members:
  - userId: member-001
    name: Alice
    signInCode: 'REPLACE_WITH_A_UNIQUE_RANDOM_CODE'
  - userId: member-002
    name: Bob
    signInCode: 'REPLACE_WITH_ANOTHER_UNIQUE_RANDOM_CODE'
```

- `userId` 是稳定且唯一的成员标识；成员改名时应保留原标识。
- `name` 是登录时填写的姓名，应为每个人设置不同的名字。
- `signInCode` 是该成员自己的登录邀请码；将占位符替换成各不相同的随机值，单独发给对应成员。不要把真实名册提交到仓库。

Web 实例支持配置热更新，保存有效名册后生效；首次配置需启动实例。移除成员时，从列表删除对应条目，其旧登录和连接会失效。名册为空时无人能够登录。

> 上述内容说明目录和成员配置。完整的团队部署模板、启动脚本和安装说明正在整理，不能仅凭这段名册启动团队版。

## 后续计划：项目方法沉淀

后续希望将项目中形成的方法保存为可复用的团队经验，包括操作步骤、提示词、处理脚本、项目约定和复盘结论。

目标是让下一位成员、新建会话或新项目能够找到并复用已有方法，逐步减少重复摸索，将项目成果与完成它的方法一起保留下来。

这部分属于后续规划。当前可以先将方法和结论手动整理成项目文件，尚未提供自动沉淀、自动归档或跨项目复用系统。
